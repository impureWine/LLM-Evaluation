# 多轮购车评测协议 v1

这是供双模型联调和冻结审核的候选版本。团队确认模型额度、完整试跑及评分口径后，记录冻结提交，再开始正式运行。

## 固定输入

[场景与车型清单](../configs/evaluation-v1.json)由本项目于 2026-11-07 编制，五款车及其配置均为教学模拟。年份为模拟款年，价格为不含税费、保险与优惠的模拟裸车价，单位为万元人民币。座位数单位为座，辅助驾驶级别按清单标签判断。基础任务使用固定清单并关闭联网。两个模型共享 [模型配置](../configs/models.json)中的生成参数和[提示词](../prompts/)。

每个任务四轮，依次为初选、补充或变更需求、逐车型参数对比、最终推荐。仅前两轮改变约束，后两轮沿用第二轮的约束。清单中的参考结果只供评分使用。候选数组和最终推荐以 JSON 保存。第三轮另生成 `parameter_comparison`：用候选中的来源编号关联固定车型库，并输出价格、能源、座位数和辅助驾驶级别；车型、配置、年份与来源编号无法同时匹配的项目列入 `unmatched_candidates`，不推测或填补参数。该表代表固定数据中的车型事实，不代替对模型原始回答和指令遵循的人工评分。

## 半自动评分

从每个运行文件取四轮记录。按以下规则逐条打分，满分 100。缺失轮次按相应检查项不通过计，记录原因。车型以配置、年份和来源编号识别，人工复核时将引用与文字中的参数回查固定车型库。

| 指标 | 分值 | 判定 |
| --- | ---: | --- |
| 约束符合度 | 40 | 第一轮、第二轮各 10 分，候选非空且均落在该轮参考集合内即得分。最终推荐落在最终参考集合内得 20 分。 |
| 多轮一致性 | 25 | 第二、三、四轮分别为 10、5、10 分。该轮保留所有仍生效的硬约束，新增约束已生效，明确被替换的旧预算标为 superseded，推荐与这些约束一致，即得该轮分。 |
| 指令遵循 | 15 | 第一轮有初选名单得 3 分，第二轮有更新后的名单得 3 分，第三轮逐车型列出价格、能源、座位和辅助驾驶等级得 5 分，第四轮给出一款车型、理由与取舍得 4 分。每轮需通过结构校验并满足最多一个追问，才可获得该轮分。 |
| 信息真实性 | 20 | 每轮 5 分。该轮车型及全部可核实的配置、年份、价格、能源、座位、辅助驾驶等事实与车型库一致，且候选来源编号能对应该车型，即得分。把清单外事实说成已知，或引用其他车型来源，该轮为零。 |

任务成功定义为四轮通过结构校验，最终推荐符合有效硬约束，且信息真实性为 20 分。成功率分母为计划内已发起的任务，失败、超时及中断计入分母；未发起项单列。比较同一场景重复运行的分数范围与成功数，多款有效车型之间的切换按同一口径评分。耗时取任务墙钟时间，token 按各轮可读到的用量求和并单列缺失；汇总时注明样本数及是否包含失败任务。记录错误和补跑，不以补跑覆盖原文件。

## 运行顺序

在仓库根目录执行：

```powershell
$env:PYTHONPATH = 'src'
python -m llm_eval.evaluate --dry-run
# 确认本地密钥、额度和团队授权后执行联调，每个模型和场景一次
python -m llm_eval.evaluate --allow-disabled-model --repetitions 1
# 完成联调及冻结审核后，从冻结提交开始运行三次重复
python -m llm_eval.evaluate --allow-disabled-model
```

联调批次标为 pilot。完整矩阵的日志标为 evaluation_candidate，只有冻结提交与实跑条件核对无误后才可纳入正式统计。日志保存在 Git 忽略的 runs 目录；公开前先脱敏。三次重复计划为两模型 × 三场景 × 三次，合计 18 次，每次四轮。

## 产品体验与采访交接

对两款实际产品使用同一组购车操作，分别记录产品入口、主要功能、任务完成情况、观察到的优缺点和截图。安排计算机或软件相关专业学生实际使用 10–30 分钟；记录背景、选择理由、任务需求、操作时间、实际行为、困难和改进建议。经受访者同意后留存脱敏图文，区分观察与原因推测。
