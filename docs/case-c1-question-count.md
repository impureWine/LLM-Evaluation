## 2. 现象

模型在 `next_question` 字段中给出两个并列的信息请求：

> 您更倾向于纯电车型（A）还是插电混动车型（B）？或者您对车辆的续航里程有特殊要求吗？

同一轮的其他客观指标：

| 指标 | 值 | 说明 |
| --- | --- | --- |
| JSON 结构校验 | 通过（`valid: true`） | 字段齐全、类型合法 |
| `finish_reason` | `stop` | 非截断、非超时 |
| 纠正重试次数 | 0 | 一次输出即通过结构校验 |
| 端到端耗时 | 89.282 s | 关闭思考模式后 |
| token | 2456（输入 1773 / 输出 683） | 单次调用 |
| 候选车型 | 示例紧凑型轿车A、示例紧凑型SUV B | 来源编号 `smoke-car-001`、`smoke-car-002` |
| `final_recommendation` | `null` | `status: candidate_only` |

也就是说：**JSON 合法、候选与参数和给定题库一致，但“一次只问一个最关键的问题”这条语义要求被违反**。

## 4. 按冻结口径的判定

- D2 规定：第 1—3 轮的 `next_question` 超过一个问句，即失掉该轮指令遵循分。本案例计得 2 个问句，因此第 1 轮指令遵循 3 分不通过。
- 该项在正式批次中会以 `override` 进入 `review-queue.csv`：自动结论为不通过，人工可凭上下文改判。
- **本案例的复核结论：维持不通过，不改判。** 理由是两句分别索取不同信息——“选纯电还是插混”是车型取向，“续航有无特殊要求”是补一条新约束；回答其中一个无法替代另一个，属于两次信息索取，而不是同一个问题的两种表述。
- 该记录只有一轮，不满足 `scoring.py` 的四轮输入格式，因此本案例是**人工套用口径**得出的判定，不是程序自动打分。正式四轮批次里才由代码自动判定并进入复核队列。

### 什么不算两个问题

为让口径可复查，下面三类写法不扣分：

| 写法 | 问号数 | 判定 |
| --- | ---: | --- |
| 您更看重续航还是智驾？ | 1 | 通过（一个二选一） |
| 纯电 A 和插混 B，哪个更合适？ | 1 | 通过 |
| 选 A 还是 B？另外预算能到多少？ | 2 | 不通过（两次索取，与本案例同类） |

按问号计数是近似口径，不追求语义精确；正因如此才保留 `override` 改判通道，但改判必须记录理由。

## 5. 可能原因

**观察到的部分**（有记录支撑）：

- 输出结构与字段类型完全合法，`finish_reason` 为 `stop`，无重试，说明不是截断或接口异常导致。
- 模型在同一轮内同时处理“车型取向”和“续航要求”两件事，且把两件事写进同一个字符串字段。
- 该轮候选与题库一致：001（18.8 万元、纯电、5 座、L2）与 002（17.6 万元、插混、5 座、L2）都在预算内，003（23.2 万元）超预算且未出现。因此本案例的下降项只有追问数量，不涉及编造或超预算。

**假设**（内部机制不可观察，标注为假设，不作确定性断言）：

- 假设 H1（提示词）：系统消息提出“最多一个问题”，但提示词和 Schema 都没有给出“单问题”的正例，模型可能把“二选一加一个补充要求”理解为一个复合问题。
- 假设 H2（模型策略）：在信息不足时，模型倾向一次收敛多个不确定性以减少轮次，未按“信息增益最大”只选一个。
- 假设 H3（评测链路）：结构校验只检查类型与必填字段，语义约束没有被任何检查覆盖，因此该输出在链路上表现为“完全通过”。

**已排除**：接口层（HTTP 200、`finish_reason=stop`、token 用量正常、无重试）与上下文截断，均不是本案例原因。

## 6. 影响与后续

- 评分影响：单轮 3 分；若 1—3 轮都出现，单次任务最多影响 9 分。
- 产品影响：用户一次需回答两件事，容易只答一件，下一轮模型可能基于不完整回答继续推进。
- 复现性：本案例只有一次调用，只能证明“该次出现”，不能推断发生率。若需估计频率，应在正式批次中统计各轮问句数分布，或另设补测批次；补测须单独标注，不得并入 18 次正式矩阵。
- 案例用途：第一部分自动化测试小节的现象描述，以及第二部分 BUG 原因分析与工程建议的证据来源。

## 7. 局限

- 单样本、单模型、单场景，且属于接入冒烟（pilot），不是正式评测。
- 冒烟题库为三款示例车，与正式五车题库不同；本案例的结论只针对追问口径，不引用该次冒烟的分数。
- 本案例不计入 18 次正式运行，也不进入成功率分母。
- 语义判断依赖人工复核，`override` 的裁决理由需与其他复核记录一起归档，避免“按主观印象改分”。
