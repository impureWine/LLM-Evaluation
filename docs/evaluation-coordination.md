## 验收清单

逐项补充提交链接或运行编号，由验收人复核后打勾。

- [ ] **模型与公平条件（程群、李泉毅）**：两个不同模型均通过完整任务联调，记录平台、请求与回显 ID、日期及主要参数。双方使用相同场景、数据、提示词及输出要求。说明参数差异和联网条件。
- [ ] **数据与评分冻结（庄剀涵、关欣）**：至少三个场景均有预算、用途和预算外硬约束，至少一个在后续轮次修改需求。固定车型库标注年份、配置、价格口径、单位、来源日期或模拟属性。正式运行前冻结预期集合、评分细则、提示词和配置，保存 Git 提交与文件指纹。
- [ ] **执行及解析（李泉毅、程杰、曾俊涛）**：两模型各场景独立运行三次，至少 18 次完整任务。任务内继承上下文，任务间隔离。日志关联候选、对比表、最终推荐及原始响应，保留失败和重试，联调单列。
- [ ] **汇总与复现（程杰、曾俊涛）**：报告约束符合度、一致性、指令遵循、真实性、成功率、波动、耗时和 token，写清分母、缺失值、统计范围和单位。费用有证据时列出。抽查图表到原始运行的对应关系，并按 README 独立复跑。
- [ ] **体验与采访（郭昱祺）**：两个产品均有功能体验、截图、优缺点及改进意见。计算机或软件相关专业受访者实际使用 10–30 分钟，保留脱敏图片及文字，分列观察与推测。目前已有功能及证据分析、官方截图、NABCD和采访包；真实采访与双产品完整操作仍待补齐，保持未勾选。
- [ ] **案例与方案（关欣、程群）**：至少两个失败或边界案例可回溯到运行记录，单列补测。对比一项改进与至少一个备选方案，写明选择理由和验证方法。将已观察到的现象与内部原因假设分开。
