## 1. 数据选择与实验边界

本次沿用团队仓库已有的五款**教学模拟车型**。全部车型、配置与价格都是教学设定，没有对应真实品牌或厂商报价。作业原文明确允许这种数据形式，但不能将其称为真实市场数据。保留原输入有利于团队接入、评分和联调结果保持可比较；本次新增来源、场景语义及参考答案材料，不改写原车型参数、场景消息和提示词。

车型与运行场景的唯一主数据为 [`configs/evaluation-v1.json`](../configs/evaluation-v1.json)。新增的 [`vehicle-sources-v1.json`](../data/vehicle-sources-v1.json)记录来源及字段字典，使用 `source_id` 关联车型。机器可读的逐轮约束与完整四轮脚本见 [`scenario-rules-v1.json`](../configs/scenario-rules-v1.json)。

两个模型均应在同一次任务开头接收同一车型库。基础实验关闭联网，不能调用外部车型知识补全参数。未来若替换成真实车型或引入联网，须新建数据版本并重新计算参考集合，扩展实验单独报告。

## 3. 三个场景与逐轮需求变更

三个场景都有用途、预算及预算以外的硬约束，每个任务共四轮。用户消息与现有运行器逐字核对，新增的结构化规则只供参考计算与评分，不改变模型接收的原消息。

| 场景 | 用途 | 第1轮有效硬约束 | 第2轮变更 | 第2—4轮有效硬约束 |
| --- | --- | --- | --- | --- |
| city | 城市通勤 | 裸车价≤18万；纯电；至少5座 | 新增 L2 | 裸车价≤18万；纯电；至少5座；L2 |
| family | 家庭出行 | 裸车价≤24万；至少7座 | 新增插电混动 | 裸车价≤24万；至少7座；插电混动 |
| change | 周末跨城 | 裸车价≤24万；至少5座；插电混动 | 预算由24万改为19万 | 裸车价≤19万；至少5座；插电混动 |

### 场景一：city

- 第1轮：“城市通勤，预算最高18万元，必须纯电、至少5座。先列出候选。”
- 第2轮：“仍按原条件，必须具备 L2 辅助驾驶。请更新候选。”
- 生效规则：L2 从第2轮开始生效，预算、能源、座位条件继续有效。

### 场景二：family

- 第1轮：“家庭出行，预算最高24万元，至少7座。先列出候选。”
- 第2轮：“必须是插电混动。请保留预算和座位数要求，更新候选。”
- 生效规则：插电混动从第2轮开始生效，24万元预算和七座条件继续有效。

### 场景三：change

- 第1轮：“周末跨城，预算最高24万元，至少5座，必须插电混动。先列出候选。”
- 第2轮：“预算上限改为19万元，其余要求保留。请更新候选。”
- 生效规则：发出第2轮消息时，19万元替代24万元；旧预算标为 `superseded`，新预算为 `active` 且来源轮次为2，能源与座位约束保留来源轮次1。第3、4轮不恢复旧预算。

### 三个场景共用的后两轮

- 第3轮：“请按车型对比有效候选的价格、能源、座位数和辅助驾驶级别。在每款候选的 why_fit 中逐项列明参数，继续保留来源编号；并在 parameter_comparison 数组中逐车结构化列出 source_id、model、trim、year、price_wan、energy、seats、adas，数值必须与车型库完全一致。”
- 第4轮：“请从仍符合约束的候选中选出一款。返回最终推荐、理由与取舍。”

第3轮只对当前合格车型进行比较，第4轮从同一集合中选出一款。原框架暂在 `why_fit` 保存参数，独立参数表的提取由程杰接续；这里提供的车型表是输入事实表，不冒充模型输出表。

## 4. 参考车型集合及判定依据

对每轮所有有效硬约束求交集：

`R(s,t) = {v ∈ 固定车型库 | v 满足场景 s 在第 t 轮全部 active 约束}`。

| 场景 | 第1轮 | 第2轮 | 第3轮 | 第4轮允许的最终推荐 |
| --- | --- | --- | --- | --- |
| city | SIM-A、SIM-E | SIM-A、SIM-E | SIM-A、SIM-E | SIM-A 或 SIM-E |
| family | SIM-C、SIM-D | SIM-C | SIM-C | SIM-C |
| change | SIM-B、SIM-C | SIM-B | SIM-B | SIM-B |

这些是**完整可行集合**，不是模型必须复述的答案，也不规定多个合格车型的唯一排名。是否要求候选列全，由关欣最终冻结的评分口径决定；当前协议的约束符合度检查允许非空合格子集。最终推荐在合法集合中切换，不能单独视为不稳定。

| 关键核验点 | 参考解释 |
| --- | --- |
| city 保留 A、E | 两车都在18万元内、纯电、5座、L2；不能仅依据“智驾版”名称声称 E 的功能更强 |
| family 第2轮排除 D | D 虽为7座且未超24万元，但能源是燃油，不满足新增的插电混动约束 |
| family 不能改推 B | B 虽为插电混动且价格更低，但只有5座；新增能源要求不取消七座要求 |
| change 第2轮排除 C | C 的22.6万元超过新预算19万元；改推 B 是正确响应需求变更，不属于前后矛盾 |
| change 不能改推 A、E | 两者虽在19万元内，但为纯电；不能遗忘原插电混动条件 |

若用户额外偏好最低价格，city 可选 SIM-A；原场景没有明确这个偏好，所以不能据此扣除推荐 SIM-E 的得分。跨城用途只作场景背景；缺少续航与充电数据时，不得宣称 B 的长途能力已得到验证。

完整逐轮参考答案、约束状态和每辆被排除车型的失败条件见 [`reference-answers-v1.json`](../data/reference-answers-v1.json)。它由规则计算产生，并与现有配置中的 `expected_initial` / `expected_final` 核对。运行器只发送场景请求和车型数据，不发送参考集合；校验工具通过替换参考字段为哨兵值确认消息不受影响。

## 5. 离线校验、版本与交接

在仓库根目录执行（Python 3.8+；无需 API Key、联网或额外依赖）：

```powershell
$env:PYTHONPATH = 'src'
python -m llm_eval.dataset
python -m llm_eval.evaluate --dry-run
python -m unittest discover -s tests -v
```

`llm_eval.dataset` 默认只读，检查车型字段、来源覆盖、三场景十二个轮次的参考集合、脚本与运行器一致性、答案隔离及文件指纹。失败退出码为1，不会悄悄更新答案。校验记录见 [`data-validation-2026-11-09.json`](../evidence/data-validation-2026-11-09.json)。

[`release-v1.json`](../data/release-v1.json)记录十个输入文件的 SHA-256，覆盖数据、规则、参考答案、模型配置、提示词和评分协议。采用 UTF-8 文本、去 BOM、换行统一 LF 的方式，与现有运行器读取配置的方式一致，避免 Windows 换行造成伪差异。状态为 `prepared_for_team_freeze`，不是已批准冻结的声明。

确需修改数据时，先记录原因及对已运行批次的影响，核对新预期集合，再显式重建：

```powershell
python -m llm_eval.dataset --write-reference --write-lock
```

## 6. 局限与补测建议

该小型数据集用于检查约束筛选、上下文保持及事实引用，不能证明模型具备真实购车专业能力。city 新增 L2 后恰好不改变候选集合，主要检查约束记录，筛选难度有限。基础三场景均有解，没有覆盖无解或数据缺失情况下的澄清策略。

可单独追加预算边界和无解测试，例如把 change 第2轮预算设为18.6万元时应保留 B，设为18.5万元时应无合格车型。这里只提出补测设计，未把它们作为已执行的模型失败案例或18次正式实验的一部分。现有单元测试已检查包含预算边界、超预算拒绝、条件保留、预算替换、来源错配与脚本漂移。

基础场景的第1轮均有两款候选，符合初始提示词数量要求；第2轮的 family 和 change 仅剩一款，不得为了凑两款而加入不合格车型。这一点应写入评分复核说明。
