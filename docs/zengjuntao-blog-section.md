# 量化对比与稳定性分析（曾俊涛负责段落）

> 本段落是待合稿的实验方法与结果模板。正式运行和评分尚未完成，所有“待填写”均不得替换为推测数字。

## 统计范围与口径

计划对 `glm-4.7-flash` 和 `glm-4.7` 在城市通勤、家庭出行、需求变更三个场景各独立运行三次，每次四轮，共 18 次完整任务。联调、冒烟和后续补测单独标识，不计入预定的正式矩阵。每次运行应记录模型实际回显 ID、场景、重复序号、配置与提示词指纹、各轮原始响应、错误与重试、墙钟耗时及 token 用量。

**任务成功率**按[评测协议](evaluation-protocol-v1.md)定义：四轮输出契约通过（含第三轮参数表审计）、最终推荐满足当前有效硬约束、信息真实性按冻结规则通过。分母为计划内已发起的任务，失败、超时或中断也计入；未发起的任务单列。运行统计脚本生成的“输出契约完成率”不等同于购车任务成功率。

**稳定性**按模型与场景分别报告三次独立运行的成功数、总分及各维度分数的范围（最大值减最小值）。当多款车型都满足约束时，最终车型不同本身不构成不稳定。三次重复的样本量较小，不能据此推断行业整体排名。

**延迟**同时列出单次完整任务墙钟时间（秒）及可记录轮次的平均响应时间（秒）。超时和重试应保留在原始记录中，并说明汇总是否包含失败任务。**token**按各轮可读取的 prompt、completion 与 total 用量求和；缺失用量单列，不把缺失值算作 0。只有平台账单或官方价格与实际用量可核验时才计算费用，并注明币种和计价日期。
