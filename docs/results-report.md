## 生成

在仓库根目录运行；如果 `runs/` 中只有一个兼容正式批次，可直接执行：

```powershell
$env:PYTHONPATH = 'src'
python -m llm_eval.report
```

输出默认写入 Git 忽略的 `evidence/results/`。可用 `--out` 指定其他目录。若存在多个兼容批次，需在 `--runs` 指定其中一个批次目录，不能合并批次。命令只读取日志，不发起 API 请求。

## 输出

- `candidate-extraction.csv`：第 1、2 轮候选及来源编号、车型事实、轮次参考集合符合情况。
- `parameter-comparison.csv`：第 3 轮模型实际返回的结构化字段、逐列固定车型标准值、符合集合状态及差异。
- `final-recommendations.csv`：第 4 轮最终车型、理由、取舍及是否落在允许集合。
- `run-summary.csv`：每次运行的四轮输出契约完整性、错误类型、墙钟耗时、token、比较表核验和最终推荐检查。
- `model-summary.csv`：按模型和场景统计的样本数、四轮输出契约完成率、耗时、token（各自带有效样本数）、候选和参数核验计数。
- `score-template.csv`：每次运行的空白人工 rubric 评分行。
- `reviewed-scores.csv`：导出实际纳入总分汇总的人工评分。
- `model-comparison.svg`：各场景四轮输出契约完成率与平均墙钟耗时；样本数随图展示。
- `score-comparison.svg`：各场景人工复核总分均值；未填写分数时显示“待人工评分”。
- `report.json`：兼容性、样本量、指纹和导出状态。

手动复核后，填充 `score-template.csv` 中四项 rubric 分数及复核人，并运行 `python -m llm_eval.report --scores evidence/results/score-template.csv`。四项分别为约束符合度（0–40）、多轮一致性（0–25）、指令遵循（0–15）、信息真实性（0–20）；工具只验证上下限并相加，不替复核者评分。若日志不在默认 `runs/`，用 `--runs` 明确指定单个批次目录。存在多个兼容批次时必须先选择一个，避免误合并不同正式矩阵。

只有 `batch_kind=evaluation_candidate` 且车型/提示词/评分指纹与当前版本完全一致的记录会进入汇总。token 只有在服务端响应明确提供 usage 时才计入，漏报会留空并计入缺失轮数。四轮输出契约完成率只表示 JSON 结构和参数对比表审计均通过，不代表约束符合度、答案正确性或模型总分。没有人工评分时不生成100分总分；自然语言中的全部事实真实性仍需人工按评分协议复核。每个场景三次运行的样本量较小，应在报告中保留分母、缺失项和失败记录。
