# 庄剀涵：大模型与购车助手的市场概况、用户及商业模式

负责人：庄剀涵（102400435）

资料核验日期：2026-11-09（北京时间）

## 1. 研究对象与统计口径

本报告分析“大模型服务及其上层购车决策助手”的产品机会。需要区分三个层次：大模型供应商向开发者提供模型能力，Agent 应用把模型组织为任务流程，购车助手则是其中的垂直应用。总体市场、某个平台收入和本课程原型的可服务市场不是同一指标。

以下市场金额引用机构公开报告摘要，属于商业研究估算和预测；用户规模引用 CNNIC 统计报告发布说明。统一保留原币种与统计时间，不把全球美元金额换成未经说明的人民币口径，不把预测值当作已实现收入，也不把用户数视为付费客户数。检索时实际读取了正文，关键短摘录见[来源核验记录](../evidence/market-source-excerpts-2026-11-09.md)，结构化引用见 [`market-sources-v1.json`](../data/market-sources-v1.json)。

## 2. 市场规模与增长

| 统计对象 | 2025年规模 | 2026年估算 | 2033年预测 | 预测年复合增长率 | 来源与边界 |
| --- | ---: | ---: | ---: | ---: | --- |
| 全球大语言模型整体市场 | 74亿美元 | 98亿美元 | 956亿美元 | 2026—2033年38.5% | M1，Grand View Research；包含云和本地部署，不是纯 API 收入 |
| 全球 AI Agent 市场 | 76亿美元 | 109亿美元 | 1,829亿美元 | 2026—2033年49.6% | M2，Grand View Research；跨行业应用，不是购车助手收入 |

以上将原文 USD billion 乘以10转换为“亿美元”。2025年的数值也是机构市场估算，不是官方审计统计；2026年是估算，2033年及 CAGR 是预测。公开摘要未明确显示发布日期，故以2026-11-09访问到的报告版本为准，不伪造发布日期。

两个市场存在产业链和分类交叉，不能把74亿与76亿美元相加作为“总机会”。38.5%和49.6%也不是2025年同比增速，不能据此声称未来每年都会实现对应增长。完整研究方法和细分底表未获取，因此这组数据用于说明市场方向和数量级，不用来推算本项目收入。

**大模型 API 窄口径的限制。** 本次未取得可独立核验、能从模型训练、私有化部署和其他服务中拆分出来的纯 API 收入规模。M1 是相邻总体市场参照，不能改写成“全球大模型 API 市场为74亿美元”。本报告以 M2 提供作业要求的 Agent 市场规模与增速，并以官方 API 计费资料分析模型服务的收入机制。

对于购车场景，价值并非回答更多车型知识，而是减少用户重复整理需求和逐项查证的时间。预算、能源、座位等条件的交集，以及需求变化后重新比较的过程，适合组成可审计的任务流程。这是基于任务特点的产品判断，尚未由团队真实采访或正式模型实验验证。

## 3. 直接用户与潜在用户

| 用户层次 | 可核验规模或状态 | 对本项目的含义 |
| --- | --- | --- |
| 中国生成式 AI 使用者 | 2025年12月6.02亿人，较2024年底增长141.7%，普及率42.8%（M3） | 是整个生成式AI品类的现有用户，不是 GLM 用户、月活、付费用户或购车助手用户 |
| 较新的品类用户规模 | 截至2026年上半年突破7亿人、普及率超50%（M4） | 是报告给出的阈值，不能写成精确7.00亿；也不与2025年数值混成同一期统计 |
| 潜在 C 端触达基础 | 2025年12月中国网民11.25亿人（M3） | 表示在线分发的广泛基础；不等于11.25亿人都有购车计划或付费意愿 |
| 潜在企业基础 | M3 发布说明称中国中小企业超过6000万家 | 是广义企业群体，并非采用模型、需要购车助手或已付款的客户数 |
| 模型 API 的直接用户 | 接入模型的开发者、软件团队和企业技术部门；本次未获得去重后的开发者/付费企业总量 | 不以 API Key 数、请求数、产品备案数替代客户人数 |
| 购车助手的直接用户 | 有真实购车或换车需求的消费者；潜在付费方还包括经销商或汽车信息平台 | 尚未部署的本课程原型没有可核验的活跃或付费用户统计 |

M4 还报告，76.0%的生成式 AI 用户会让其回答问题。这支持“以问答形式收集需求”的交互可理解性，但不能据此计算购车用户数，更不能推导汽车推荐的正确率。

潜在用户可以按需求进一步区分：首次购车者需要理解参数与预算口径；家庭换车者需要同步考虑座位及多位家庭成员的条件；已有车型 shortlist 的用户需要来源可查的比较；经销商和汽车平台需要把咨询转化成结构化需求。这些是待采访验证的画像假设，不是本次已经观察到的真实受访者结论。

若需要估算可服务规模，应先明确地区和时间窗，例如“未来12个月内计划购车、愿意在线咨询、可被本产品渠道触达的人群”。可采用：

`可触达购车用户 = 有购车计划的人数 × 在线咨询比例 × 本产品渠道可触达比例`。

`预期付费用户 = 实际试用人数 × 经验证的付费转化率`。

目前这些交集和比例没有来源，所以不填写推算人数。汽车销量是车辆交易流量，汽车保有量是存量，网民规模是人数，三者也不能直接充当购车助手客户数。后续采访与小规模试用应重点验证需求频率、信任条件和付费意愿，而不是直接套用大市场比例。

## 4. 模型平台的商业模式资料

智谱官方把平台定位为一站式模型即服务，提供 API 调用、精调、推理、联网搜索及知识库等能力（B2）。API 定价文档明确采用按量计费，并区分输入、输出、缓存命中及缓存存储费用（B1）。这说明供应商出售的不只是模型权重，还包括托管推理、服务稳定性、开发接口和配套工具。

截至访问时，官方价格页列出以下与团队模型有关的条目：

| 模型与计费条件 | 未命中缓存输入 | 输出 | 缓存命中输入 | 口径 |
| --- | ---: | ---: | ---: | --- |
| GLM-4.7，输入[0,32K)，输出[0,0.2K) | 2 | 8 | 0.4 | 元/百万 tokens |
| GLM-4.7，输入[0,32K)，输出≥0.2K | 3 | 14 | 0.6 | 元/百万 tokens |
| GLM-4.7，输入[32K,200K) | 4 | 16 | 0.8 | 元/百万 tokens |
| GLM-4.7-Flash，页面标注200K上下文 | 免费 | 免费 | 免费 | 页面当时定价；不保证账号额度、并发或未来价格 |

上述条目的缓存存储列在访问时标为“限时免费”。区间和价格均来自同一页，不可只取最低价用于全部请求。页内价格会更新；正式实验的计价版本、平台账单与可获得的用量记录应另行留存。这里没有产生新的实际调用费用，也不改动程群的模型参数或启用状态。

**商业机制分析（推断）。** 免费模型可降低开发者的接入门槛，按量付费模型覆盖更复杂需求，知识库和检索等服务可扩大客户接入范围。免费接入是否最终增加付费转化、某模型是否具备成本优势，都需要真实收入和实验数据才能验证；本报告不将这一推断表述成平台已公开的经营成绩。竞争优势应在本项目中落实为相同约束下的成功率、可核验成本、延迟和接入维护成本，而非仅引用厂商宣传。

## 5. 购车助手的商业模式选择

| 方式 | 可能付费方及收费对象 | 成立条件与取舍 |
| --- | --- | --- |
| 单次深度比较报告 | 消费者，为可溯源的车型比较和需求方案付费 | 购车低频，持续订阅留存未必适合；需先验证付费意愿和报告质量 |
| 企业订阅或按会话收费 | 经销商、汽车内容平台，为咨询整理和客服辅助付费 | 需求较持续，但需要数据更新、接入维护、审计及服务保障 |
| 授权线索服务 | 经用户同意后，由合作商家为有效咨询线索付费 | 推荐排序与商业合作应披露并区分；不能把广告车型包装成最符合硬约束的选择 |

对课程原型，先验证固定数据下的约束筛选和可追溯解释。若后续继续产品化，可优先试验“消费者基础使用＋企业咨询辅助”的组合，再根据真实转化决定收费，而不是现在宣称已有商业闭环。这一建议供郭昱祺的 NABCD 和功能优先级分析使用，不替代其采访结论。

与通用聊天产品相比，可形成差异的部分包括：明确的预算口径、按配置与年份关联的数据来源、需求变更的版本记录、无解时解释冲突以及把未知参数显式留空。车型更新与来源维护会持续产生成本，因此真实商业产品不能长期使用本实验的教学模拟库。

## 6. 从 token 单价到完整任务成本

一次四轮任务的模型费用应按所有实际请求求和，包括重试和纠正请求，以及各轮重复传入的历史上下文：

`C模型 = Σ[(输入tokens−缓存命中tokens)×输入单价 + 缓存命中tokens×缓存单价 + 输出tokens×输出单价] / 1,000,000 + 缓存存储费用`。

每次请求先按模型和长度区间选取适用单价。若日志缺少缓存分类，不能凭空假定全部命中；可明确采用全部未命中的估算口径，并与实际账单区别。搜索、知识库、托管、数据维护和人工核验费用另算。

**仅作算式示例：** 假设 GLM-4.7 的四次请求均落在“输入<32K、输出≥0.2K”档，四轮累计未缓存输入10,000 tokens、输出2,000 tokens，无纠正重试、工具或存储收费，则模型费用为 `10,000×3/1,000,000 + 2,000×14/1,000,000 = 0.058元`。这不是本次实验实测费用，也不是对任何用户的报价。

商业上更应比较 `单位成功任务成本 = 统计批次全部成本 / 成功任务数`，把失败成本也计入分子。成功数为0时该指标不可计算，不应填0。免费 API 也仍有数据、托管、维护和质量检查成本，不能直接得出产品运营成本为零。

## 7. 可用于博客的结论

公开资料表明，生成式 AI 已形成大规模用户基础，Agent 应用也处在机构预测的快速增长市场中。但这只能说明存在应用机会，不能证明购车助手已经有对应的付费需求。对本项目，产品价值应通过“需求变化后是否仍满足硬约束、车型事实是否可核验、完成一次有效决策的成本与延迟”来验证。先完成实验和真实用户反馈，再讨论模型选型及商业扩张，能够避免把宏观市场增长误当作具体产品成功的证据。
