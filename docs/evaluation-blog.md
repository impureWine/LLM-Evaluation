## 第一部分 调研与评测

### 模型一 GLM-4.7-Flash

**体验。** 待汇入功能操作截图、真实采访及改进意见。

**自动化测试。** 智谱 BigModel 在 2026-11-07 的一次成功冒烟调用回显模型 ID `glm-4.7-flash`。记录耗时 89.282 秒、总 token 2456，结构校验通过。输出的追问字段包含两个并列问题，提示评分时还需检查内容是否遵循“最多一个问题”的要求。见[原始冒烟记录](../evidence/zhipu-glm-4.7-flash-smoke-success-2026-11-07.json)及[接入说明](model-access-and-configuration.md)。

**结论。** 已有记录支持继续联调结构化输出链路。任务成功率及建议使用场景待正式评测。

### 模型二 GLM-4.7

**体验。** 待汇入与模型一使用相同维度的体验和采访记录。

**自动化测试。** 仓库配置保留智谱 BigModel 的 `glm-4.7`，默认禁用。接入材料记载该 ID 出现在账号的模型列表中，待确认额度、价格及团队授权后做完整链路试跑，并记录实际回显。见[模型配置](../configs/models.json)。

**结论。** 当前证据支持保留为对照候选，正式表现待实测。

### 公共实验方法与量化对比

基础实验拟关闭联网。每次从相同固定车型库开始，按初步候选、补充或变更需求、参数对比、最终推荐推进。每个模型对城市通勤、家庭出行、需求变更三个场景独立执行三次，合计 18 次。运行前锁定数据、场景、预期车型集合、提示词、评分规则和配置。同一次运行继承对话历史，下一次重新建立消息列表。当前共享配置为 temperature 0、top_p 1、max_tokens 4096、非流式、JSON 输出、关闭思考，具体以冻结版及服务端支持情况为准。

正式结果待附评分表、按场景的成功数与样本数、耗时与 token 汇总及至少两个可回溯案例。失败调用与重试单独保留。方案比较见[技术改进说明](technical-improvement.md)，效果验证待正式证据。

## 第二部分 分析

### 开发时间估计

估计对象为本次课程的可复现评测工具、证据和报告。以八名成员分工并行、复用现有 Python 接入代码和模型接口为前提，每人可投入约 8–10 小时。下表为计划工作量，单位为人时。

| 工作包 | 人时 | 估算依据 |
| --- | ---: | --- |
| 需求、验收与试跑组织 | 5 | 核对原文、确定实验矩阵、组织一次冻结复核 |
| 模型接入与提示词 | 7 | 两模型试调用、结构输出及异常联调 |
| 车型库、场景及市场材料 | 9 | 三组需求及预期集合、数据和市场来源复核 |
| 多轮框架与运行日志 | 11 | 消息隔离、批量运行、超时重试及保存 |
| 评分与边界案例 | 9 | 四个质量维度及至少两条证据回溯 |
| 输出解析、图表与核对 | 8 | 提取三类产物、汇总与抽查 |
| 体验、采访与产品规划 | 10 | 双产品体验、采访记录和 NABCD |
| 正式执行与复现 | 7 | 配置冻结后运行 18 次，复核日志及统计 |
| 博客整合、脱敏及提交 | 7 | 合稿、目录与材料链接、发布复核 |
| **合计** | **73** | **约 9.1 人时/人，按分工分配** |

正式运行依赖模型联调、数据和评分冻结，随后才能完成图表与选型结论。按 18 个任务、每任务规划四轮估算，至少 72 次基础模型请求，纠正和重试会增加调用。实验当天用小批次实测耗时更新排期。11 月 8 日计划冻结，9 日完成运行，10 日合稿并预留审核时间，11 日 20:00 前完成内部提交目标。

### 程序软件工程与商业分析

程序层把购车需求、车型参数和多轮消息组织成输入，由适配器发起请求，解析结果按输出契约校验。工程层将数据、提示词、评测和汇总拆为可分别验收的模块。按运行编号关联输入版本、输出、错误和评分，可区分场景变更、模型行为与解析故障。正式运行前锁定配置及指纹，改动后记录影响范围，避免在同一汇总中混用条件。

商业层由团队结合市场资料补齐。模型接入时记录实际 token、可核验的计价口径和额度，作为后续单位任务成本分析的输入。

### 同类产品对比与选型建议

联调阶段先用已经通过一次结构输出冒烟的 `glm-4.7-flash` 排查框架问题，同时保留 `glm-4.7` 作为对照候选。正式选型先看预算等硬约束是否满足、需求变更后是否沿用已被替换的限制，以及车型事实是否正确。通过这些检查的模型，再按任务成功率、耗时和可核验成本区分用途。

交互场景优先比较同等质量下的端到端延迟。涉及复杂约束变更时，只有观察到对照模型在约束符合度和多轮一致性上的收益，才考虑用额外耗时或费用交换该收益。待第一部分正式结果齐备后逐项落到两个模型。每个模型每场景仅三次运行，判断范围限于本次数据和配置。
